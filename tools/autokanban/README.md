# Автоматическая очередь raftgo

Python 3, Git, установленный и авторизованный `codex`, инструменты проверок
из AGENTS.md. Без сторонних Python-пакетов. Контроллер привязан к карточкам
S1–S4 этого репозитория; B0–B2 уже завершены.

## Запуск

Работать в единственном чистом checkout `main`:

```sh
cd /home/bogdan/rafting
./autokanban plan
./autokanban run --max-tasks 2
./autokanban status
```

`plan` читает коммиты main, не вызывает модель. `run` выполняет одну карточку
по умолчанию, `--max-tasks N` явно разрешает до N последовательных карточек.
Контроллер не создаёт ветки/worktree/копии проекта и не переключает checkout.
Карточки, код, канбан и docs/delivery.md коммитятся агентом прямо в main.
`lab1`–`lab4` создаются только вручную в DEMO по docs/delivery.md; перед каждой
DEMO очередь останавливается. После приёмки и обновления main снова `run`.

Для другого checkout: `--repo /path/to/checkout`. В нём тоже должен быть main.
Перед новой карточкой рабочее дерево должно быть чистым; при незавершённой
работе не запускать одновременно независимых агентов/редакторов Git.

Каждая карточка получает отдельную сессию Codex. Агент выполняет её критерии,
обновляет только свой статус и журнал, готовит чистый коммит и возвращает JSON.
Контроллер проверяет ветку, SHA, происхождение от исходного main, статусы других
карточек и неизменность ссылок labN. Затем независимо запускает build, test,
race, vet/lint, gofmt и diff-check на том же HEAD. Только успешные проверки
дают состояние `completed`; результат и логи сохраняются в `.git/autokanban/`.
При неуспехе коммиты агента уже остаются в main, автоматического отката нет;
незавершённое состояние блокирует запуск следующей карточки даже если агент
пометил её готовой. Сначала устранить проблему и пройти `resume`.
Контроллер не делает интеграционных коммитов, push или независимого LLM-review.
Дополнительные проверки API/UI/протокола остаются ответственностью исполнителя.

## Остановка и продолжение

Ошибка процесса/JSON/проверки, blocked/failed/needs_input, непустые ограничения,
чужая активная карточка останавливают очередь с exit=1. Автоповторов нет.

```sh
./autokanban status
./autokanban resume            # повторить незавершённый шаг/проверки
./autokanban resume --repair   # вернуть ошибку той же сессии агента
```

По умолчанию resume ограничен одной карточкой. Если остановился сам агент,
resume продолжит его сессию и сможет исправить оставленные им изменения.
При сбое независимых проверок обычный resume повторяет проверки того же SHA;
для изменений кода нужен `--repair`. Контроллер не переключит ветку обратно
и не отбросит посторонние изменения. Не удалять state.json ради обхода ошибки.
Старый формат состояния с worktree не поддерживается: сначала вручную разобрать
прежнюю незавершённую работу, сохранив её ветки/коммиты/логи.

Ctrl+C/TERM завершает текущую группу процессов, изменения сохраняются.
После SIGKILL могут остаться процессы/паузы Docker; проверить перед продолжением.
Лок в общем Git-каталоге блокирует второй контроллер, status доступен всегда.
Лок не блокирует ручные команды Git и независимых агентов.

## Доступ, лимиты и логи

По умолчанию `--sandbox workspace-write`. Если нужные Git/Docker/браузерные
операции заблокированы, очередь остановится. Для доверенного локального проекта:

```sh
./autokanban run --max-tasks 2 --sandbox danger-full-access
./autokanban resume --sandbox danger-full-access
```

Модель и авторизация берутся из настройки Codex CLI, токены контроллер не читает
и не копирует. Подключённые инструменты зависят от CLI. Таймаут карточки 7200
секунд, каждой проверки 1200: `--task-timeout` и `--check-timeout`.

Состояние версии 2, промпты, JSON, события, usage и логи проверок —
`.git/autokanban/` (точный путь показывает status). Они могут содержать код
и вывод команд, перед публикацией просмотреть. Usage хранится по попыткам,
это телеметрия токенов, не денежный счёт и не процент лимита подписки.
Новая карточка не получает историю предыдущей, resume сохраняет свою сессию.
Проверки контроллера и status/plan модель не вызывают. Жёсткого денежного или
токенного лимита нет; ограничители — число карточек, таймауты, отсутствие retry.

Проверки самого контроллера без модели:

```sh
python3 -m unittest discover -s tools/autokanban -p 'test_*.py' -v
```

Отчёты проверок — [VALIDATION.md](VALIDATION.md).
