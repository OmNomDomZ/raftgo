# Автоматическая очередь raftgo

Python 3, Git, установленный и авторизованный `codex`, инструменты проверок
из AGENTS.md. Без сторонних Python-пакетов. Контроллер привязан к формату
этого репозитория и поддерживает карточки S1–S4. B0–B2 уже завершены.

Из worktree с контроллером:

```sh
./autokanban plan
./autokanban run --max-tasks 2
./autokanban status
```

`plan` не вызывает модель. `run` по умолчанию выполняет одну карточку;
`--max-tasks` задаёт верхнюю границу. Перед каждой DEMO очередь останавливается.
DEMO выполняется и принимается обычным поручением агенту, с обновлением общего
журнала. Затем снова `run`. Следующий CORE создаётся от принятого предыдущего
этапа; заранее stage-ветки не создаются.

Общий журнал читается из `prepare/in-memory`, сейчас его checkout —
`/home/bogdan/rafting-prepare`. Он должен оставаться чистым и доступным.
Исходный грязный checkout не используется. Контроллер работает в отдельной
`chore/autokanban`, не переносит свой код в stage-ветки. Для другого пути
репозитория: `--repo /path/to/checkout`.

Каждая новая карточка получает отдельную сессию Codex и task-worktree.
Агент готовит чистый коммит, выполняет дополнительные проверки карточки и
возвращает JSON. Контроллер независимо запускает build, test, race, vet/lint,
gofmt и diff-check на этом HEAD. Лишь затем локально интегрирует результат
fast-forward и отдельным коммитом обновляет общий канбан/журнал.
Task-ветка и worktree сохраняются. Push отсутствует.

Критерии API/UI/протокола остаются ответственностью исполнителя: первая версия
не содержит отдельного LLM-review и не умеет независимо доказывать полноту
дополнительных проверок. Успешные Go-тесты не заменяют приёмку этапа.

## Остановка и продолжение

Ошибка процесса, JSON, обязательной проверки, `blocked`/`failed`/`needs_input`,
непустые ограничения, изменение целевой ветки или чужая активная карточка
останавливают очередь с exit=1. Автоматических повторов нет.

```sh
./autokanban status
# После устранения проблемы окружения — повторить проверки/незавершённый шаг:
./autokanban resume
# Чтобы вернуть ошибку проверки тому же агенту и попросить исправить:
./autokanban resume --repair
```

`resume` ограничен одной карточкой по умолчанию. Если остановился сам агент,
продолжается его сохранённая сессия. `--repair` явно возвращает карточку агенту,
даже если остановка произошла при проверке. При сбое после интеграции повторное
продолжение сверяет тот же SHA; произвольное перемещение target не допускается.
Если изменён общий журнал или остались незакоммиченные файлы после прерывания,
сначала разберите их вручную. Не удаляйте state.json для обхода препятствия.

Ctrl+C/TERM останавливает текущую группу процессов. Карточка и её изменения
сохраняются. SIGKILL/выключение компьютера может оставить процессы/паузы Docker;
перед продолжением проверьте их. Два контроллера одного репозитория блокируются
локом; он не защищает от независимого агента или ручного редактирования Git.

## Доступ и лимиты

По умолчанию `--sandbox workspace-write`. Если среда блокирует необходимые
Git/Docker/браузерные операции, очередь остановится. Для доверенного локального
репозитория можно явно использовать текущий полный доступ:

```sh
./autokanban run --max-tasks 2 --sandbox danger-full-access
./autokanban resume --sandbox danger-full-access
```

Модель не переопределяется, используется настройка Codex CLI. Авторизация —
существующая CLI; контроллер не читает и не копирует токены авторизации.
Он не меняет настройки подключённых инструментов: их наличие зависит от CLI.
Таймаут карточки — 7200 секунд, каждой проверки — 1200; параметры
`--task-timeout` и `--check-timeout` меняют эти значения.

Состояние, промпты, итоговые JSON, события, usage и логи проверок хранятся
в общем Git-каталоге, под `autokanban/` (точный путь показывает `status` при
ошибке; в основном checkout обычно `.git/autokanban/`). Логи могут содержать
фрагменты кода и вывод команд; не публикуйте их без просмотра.

`usage` сохраняется по попыткам, включая доступные input/cached/output поля.
Это телеметрия токенов, не точный счёт в деньгах или процент лимита подписки.
Новая карточка не получает историю предыдущей; возобновление своей сессии
сохраняет историю. Контроллер не вызывает модель для ожидания/опроса статуса
и не пересылает ей все старые логи. Проверки, запущенные самим контроллером,
токены не расходуют. Жёсткий денежный/токенный лимит в этой версии отсутствует;
ограничения — количество карточек, таймауты и отсутствие автоповторов.

Проверки контроллера, без обращений к модели:

```sh
python3 -m unittest discover -s tools/autokanban -p 'test_*.py' -v
```

Механизм запуска: [официальная документация codex exec](https://learn.chatgpt.com/docs/non-interactive-mode).
