# 4. CAS и распределённая блокировка

Запуск: `bash scenarios/task4/run.sh` из корня после запуска [стенда](../README.md).

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 4.1 | CAS с неверным expected | `409`, исходное значение не меняется |
| 4.2 | Два клиента одновременно выполняют CAS с одинаковым expected | Ровно один `200` и один `409`; GET возвращает значение победителя |
| 4.3 | Два клиента одновременно захватывают lock | Ровно один `201` с token и один `423` |
| 4.3 | GET, PUT, DELETE, CAS, unlock без токена на заблокированном ключе | Все возвращают `423`; запись и CAS с правильным токеном успешны |
| 4.4 | Остановить лидера | Новый лидер сохраняет блокировку и значение; без токена `423`, с токеном `200` |
| 4.4 | Полностью перезапустить кластер с прежними дисками | Блокировка и токен сохраняются после replay |
| 4.5 | Освободить блокировку; записать со старым токеном | Unlock `200`, устаревший токен `409` |
| 4.5 | Повторно захватить lock | Новый числовой токен больше предыдущего; запись и unlock старым токеном получают `423` |
| 4.5 | Удалить значение с новым токеном, создать заново без/с токеном | `200`, затем `423`/`201`: удаление значения не снимает блокировку |
| 4.5 | Освободить lock и прочитать без токена | `200`, новое значение доступно |

CAS: `POST /kv/key/cas`, тело `{"expected":"old","value":"new"}`.
Захват: `POST /kv/key/lock`; освобождение: `DELETE /kv/key/lock`.
Токен передаётся в заголовке `X-Lock-Token`. Токен — средство координации, не
авторизация. TTL нет: lock снимается явно. Сценарий использует уникальный ключ,
поэтому блокировка, оставшаяся после прерванного прогона, не мешает следующему.
Итог: `PASS task4`.
