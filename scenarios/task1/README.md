# Этап 1: выборы

Из корня репозитория:

```sh
docker compose -p raftgo-scenarios -f scenarios/compose.yaml up -d --build
bash scenarios/task1/run.sh
```

Проверяются один лидер пяти узлов, смена лидера в старшем term после pause,
возврат прежнего лидера и отсутствие лидера в меньшинстве из двух узлов.
Состояния независимы и наблюдаются по HTTP; полная Election Safety проверяется
также тестами ядра. Подробнее о cleanup и сбросе памяти — в
[общей инструкции](../README.md).

## Лист ручного показа

1. Запустите новый стенд по README. Откройте http://localhost:18001/.
   Убедитесь: «ЭТАП 1», пять свежих карточек, один Leader, общий term,
   quorum=3. Сравните /status и /election. Голос относится только к текущему
   term; votes показаны у Candidate, история голосов не восстанавливается.
2. Определите Leader по UI. В отдельном терминале выполните
   `docker compose -p raftgo-scenarios -f scenarios/compose.yaml pause nodeN`.
   При паузе origin откройте UI другой живой ноды. Через несколько секунд
   появится новый Leader с большим term; карточка паузной ноды устареет.
3. Выполните ту же команду с `unpause nodeN`: прежний процесс вернётся
   Follower, пять карточек станут свежими. RAM и PID процесса сохранены.
4. Поставьте на паузу три узла, включая лидера. Откройте UI одного из двух
   живых. Несколько окон выборов (не менее 5 секунд) наблюдайте Candidate,
   votes не более 2 при quorum=3; три карточки недоступны. Это наблюдение,
   Election Safety дополнительно проверяется детерминированными core-тестами.
5. Снимите все паузы, дождитесь одного лидера и пяти свежих карточек.
   Нажмите «Обновить». В Network запросы только того же origin.
6. Остановите весь стенд командами unpause/down из README перед сменой ветки.

Ручной показ и runner выполняются последовательно; не меняйте паузы во время
работы runner. Не вызывайте stop/start для возврата узла в этот кластер.
