# 3. KV-хранилище без блокировок

Запуск: `bash scenarios/task3/run.sh` из корня после запуска [стенда](../README.md).

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 3.1 | Создание через follower | `307` с адресом лидера |
| 3.1 | GET отсутствующего ключа; POST создания; повторный POST | `404`, `201`, `409`; повторное создание не меняет значение |
| 3.1 | GET; PUT строки с Unicode, JSON и переводом строки; PUT пустой строки | `200`, точное сохранение строк, включая пустую |
| 3.2 | Сменить лидера и прочитать значение | `200`, последнее подтверждённое значение сохранено |
| 3.2 | Приостановить и возобновить все контейнеры с сохранением RAM | После возврата значение сохранено |
| 3.3 | DELETE; GET; повторный DELETE | `200`, `404`, `404` |
| 3.3 | PUT отсутствующего ключа | `200`, ключ создан (upsert), GET возвращает новое значение |
| 3.4 | Оставить две ноды; PUT и GET на прежнем лидере | `503` или `504`, нет успешной записи или неподтверждённого кворумом чтения |

Создание: `POST /kv/key`, обновление/upsert: `PUT /kv/key`, тело `{"value":"text"}`.
Чтение и удаление: `GET /kv/key`, `DELETE /kv/key`.
После проверки ноды восстановлены. Итог: `PASS task3`.
