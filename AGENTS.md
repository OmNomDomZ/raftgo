# AGENTS.md

Инструкции для AI-агентов (Claude Code и любых других), работающих в этом
репозитории. Дублирует минимум — детали процесса и архитектуры см. в
[CLAUDE.md](./CLAUDE.md).

## Проект

`raftgo` — самостоятельная реализация Raft consensus + KV-хранилище поверх него,
на Go. Учебный проект, команда из 2 человек, разработка через отдельные ветки
и PR в `main`.

## Команды

Модуль: `raftgo`, `go 1.27.1`.

```sh
go build ./...          # сборка всего репозитория
go test ./...           # все тесты
go test -race ./...     # обязательно перед PR — Raft-логика конкурентна
go test ./raft/... -run TestName -v   # один тест с подробным выводом
go vet ./...
gofmt -l .               # список файлов с неотформатированным кодом (должен быть пуст)
```

Если появится `golangci-lint` конфиг (`.golangci.yml`) — запускать
`golangci-lint run ./...` перед PR, это заменит отдельный `go vet`.

## Правила для агента

- Одна ветка — одна декомпозированная подзадача. Не расширяй скоуп без запроса.
- Не мержить и не пушить в `main` без явной команды пользователя.
- Каждое изменение в `raft/` должно сопровождаться тестами, проверяющими
  соответствующие safety-свойства протокола (Election Safety, Log Matching,
  Leader Completeness, State Machine Safety) — не только happy path.
- `go test -race ./...` — обязательный чек перед тем, как считать задачу готовой.
- Не использовать сторонние реализации Raft (`hashicorp/raft`, `etcd-io/raft` и т.п.)
  как зависимость — только как справочный материал для идей.
- Core-логика Raft (state machine состояний узла, обработка RPC, таймеры выборов)
  должна зависеть от абстракций транспорта и времени (интерфейсы), а не от
  конкретных `net`/`time.Sleep`, чтобы её можно было тестировать детерминированно
  с fake-транспортом и виртуальными часами.
- Форматирование — `gofmt`/`goimports`, коммиты — осмысленные и атомарные.
- Если задача противоречива или требует ослабить корректность протокола ради
  простоты — остановись и явно сообщи об этом вместо тихого workaround'а.
