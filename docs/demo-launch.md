# Запуск и демонстрация lab1 на macOS

Доступны выборы, heartbeat и диагностика. Swagger содержит только GET статуса; записи строк в этом этапе нет.

## Запуск пяти терминалов

Нужны macOS, Terminal.app, Python 3 и запущенный Docker Desktop. Локальный Go
для запуска через Docker не требуется.

Из корня проекта:

```sh
python3 scripts/demo.py
```

Launcher собирает текущую версию checkout, поднимает пять Docker-узлов и
открывает пять отдельных окон Terminal.app с логами node1–node5. При первом
запуске macOS может запросить доступ к управлению Terminal.app.

- http://localhost:18001/swagger/ — Swagger с API текущего этапа.
- http://localhost:18001/swagger/openapi.json — спецификация OpenAPI.
- Порты 18002–18005, путь `/swagger/` — Swagger остальных узлов.

Встроенный экран удалён. Главная страница `/` и прежние ресурсы `/ui/...`
возвращают 404. Состояние наблюдайте через Swagger и логи.

Swagger встроен в Go-бинарник: CDN, npm и интернет для его открытия не нужны.
Используется один стенд `raftgo-scenarios` на портах 18001–18005.
Он описан в корневом `compose.yaml`; имя проекта задано в поле `name`.
Обычные команды `docker compose` из корня управляют теми же пятью узлами.

Если контейнеры уже существуют, launcher только открывает логи: он не
пересобирает, не снимает паузы и не перезапускает узлы. После смены ветки или
изменения кода сначала выполните полный `down`, затем запустите launcher снова.
Команды без запуска можно посмотреть через `python3 scripts/demo.py --dry-run`.

Повторяющийся debug-лог входящего AppendEntries выводится раз в 5 секунд
на узле; лог неудачной отправки — раз в 5 секунд для каждого соседа.
Выборы и ошибки протокола выводятся сразу. Интервал самих heartbeat остаётся
100 мс. Частота логов задаётся непосредственно в `server/http.go` и
`raft/rpc.go`: `5*time.Second`.

Закрытие окна или Ctrl+C прекращает только просмотр логов. Контейнер узла
продолжает работать; для команд управления используйте отдельный терминал.

## Выборы и отказ лидера

1. Откройте `/swagger/` каждого узла на портах 18001–18005 и выполните
   `GET /status`. Дождитесь одного Leader и четырёх Follower с одинаковыми
   term и leader_id. Swagger сам не обновляет ответ: повторяйте Execute.
2. Найдите фактического лидера. Если это node3:

   ```sh
   docker compose pause node3
   ```

3. Через несколько секунд выполните `GET /status` у оставшихся узлов.
   Появится новый лидер с большим term; Swagger замороженной node3 не ответит.
4. Верните прежнего лидера:

   ```sh
   docker compose unpause node3
   ```

5. Повторите запросы: прежний лидер должен присоединиться как Follower,
   участники согласуют лидера и term. Проверяйте также логи узлов.

Node3 — пример: подставляйте фактический ID. `/status` показывает только
текущий узел, `members` — фиксированный состав, а не статусы соседей.
Общего `/cluster/status` больше нет. Наблюдения независимы и неатомарны.
Votes значим только у текущего Candidate, история голосов не восстанавливается.
Наличие роли Leader само по себе не доказывает наличие кворума.

## Остановка и смена лабораторной

Для временного отказа используйте только pause/unpause или поддерживаемую
сетевую изоляцию: они сохраняют RAM. Не завершайте отдельный процесс с
последующим возвратом пустой памяти под прежним ID в продолжающийся кластер.

Для завершения демонстрации:

```sh
docker compose unpause
docker compose down
```

Закройте окна с логами. Все данные находятся в RAM, down удаляет пять
контейнеров и сеть. Следующий запуск создаёт новый пустой кластер.
Репликация не означает сохранение на диск.

Эта инструкция относится к текущей lab1. В других ветках могут оставаться
старые пути Compose — используйте инструкцию соответствующей ветки.

Перед сменой версии всегда удаляйте **весь** стенд через down. Сохраните
локальные правки и переключите ветку, затем выполните одинаковую команду:

```sh
git switch lab1  # либо lab2, lab3, lab4 или main
python3 scripts/demo.py
```

При отсутствии локальной lab2/lab3/lab4 её можно создать через
`git switch --track origin/labN`, подставив нужное имя. Не используйте
принудительное переключение с удалением локальной работы.

## Самостоятельные проверки

При этой доработке по поручению пользователя приложение, Docker, браузер
и тесты не запускались. Предыдущие проверки не подтверждают текущую версию.

После запуска стенда можно выполнить:

```sh
python3 tests/scenarios.py 1
```

Не управляйте отказами вручную параллельно со сценарием.
