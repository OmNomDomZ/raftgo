# Запуск и показ lab2

## Подготовка

Запустите Docker Desktop. На macOS из корня проекта:

```sh
python3 scripts/demo.py
```

Появятся пять окон Terminal с логами. Swagger: http://localhost:18001/swagger/.
Другие узлы доступны по портам 18002–18005, также по пути `/swagger/`.
Локальный Go для Docker-запуска не нужен. Swagger встроен в бинарник,
не использует CDN и внешний validator.

Стенд один: корневой compose.yaml, config/cluster.json, проект raftgo-scenarios.
Если контейнеры уже существуют, demo.py только открывает логи. Для пересборки
сначала выполните `docker compose down`. Закрытие окна или Ctrl+C прекращает
просмотр логов, а не работу процесса. `--dry-run` печатает команды без запуска.

Встроенного экрана нет. `/`, `/ui/...`, `/election`, `/cluster/status` и
`/cluster/log/{id}` возвращают 404. При проверке другой реплики меняйте порт.
Swagger показывает прошлый ответ до нового нажатия Execute.

## 1. Выборы

Откройте Swagger нескольких узлов, выполните GET /status. В установившемся
состоянии один Leader и четыре Follower с одинаковыми term и leader_id.
Кворум — три из пяти. Votes значим только у Candidate. Members — фиксированный
состав, а не текущие статусы соседей. Ответы разных узлов неатомарны.

Для показа перевыборов найдите текущего лидера, например node3:

```sh
docker compose pause node3
```

Через несколько секунд повторите GET /status на оставшихся узлах: появится
новый лидер с большим term. Swagger замороженного узла тоже не отвечает.
Верните старого лидера:

```sh
docker compose unpause node3
```

После синхронизации он станет Follower. Возможны дополнительные раунды
выборов — показывайте установившееся состояние и соответствующие логи.

## 2. Репликация строк

В Swagger откройте POST /cluster/entries/{id}. Выберите доступный узел,
в том числе follower, и отправьте:

```json
{"command":"Первая строка"}
```

Ждите 201 с index/term/committed=true. Отправьте вторую строку. Через
GET /log на разных портах сравните подтверждённый порядок. No-op — служебная
запись, не пользовательская пустая строка. Локальный хвост может отставать
или быть неподтверждённым. Пустые и повторяющиеся строки допустимы.

Прямой POST /entries также доступен. На follower он вернёт 307, поэтому
для браузера удобнее /cluster/entries/{id}: сервер сам направит запрос лидеру.

## 3. Отставший follower

Выберите follower, например node5:

```sh
docker compose pause node5
```

Добавьте две строки через Swagger другого узла. Ответы 201 покажут, что
четырёх доступных узлов достаточно. Затем:

```sh
docker compose unpause node5
```

Повторяйте GET /log на node5: подтверждённый префикс должен догнать остальные.
Не перезапускайте процесс: pause сохраняет его term, голос и лог в RAM.

## 4. Смена лидера и отсутствие кворума

Добавьте строку и дождитесь 201. Поставьте текущего лидера на паузу, дождитесь
перевыборов, убедитесь, что строка сохранилась, добавьте другую. Верните
прежнего лидера и сравните его лог.

Для показа отсутствия большинства поставьте на паузу три узла, включая
лидера. Через Swagger одного из двух оставшихся попробуйте добавить строку.
Не должно быть 201; возможны 503/504. После 504 или потери ответа исход
неизвестен: запись может подтвердиться позже. Автоповтора нет, повторное
Execute может добавить дубликат. Верните узлы через `docker compose unpause`.

## Логи

Повторяющиеся heartbeat и ошибки отправки выводятся раз в 5 секунд.
AppendEntries с записями и ошибки протокола выводятся сразу. Частота самого
heartbeat — 100 мс. Выборы видны по became candidate, voted, became leader.

## Проверки и завершение

Для автоматических сценариев после запуска стенда:

```sh
python3 tests/scenarios.py all
```

Ожидаемые результаты — PASS task1 и PASS task2. Проверяются в том числе
возврат отставшего узла, потеря кворума, смена лидера и замена конфликтного
неподтверждённого хвоста. Во время runner не меняйте паузы вручную.

Завершение показа:

```sh
docker compose unpause
docker compose down
```

После down вся RAM теряется; следующий запуск — новый пустой кластер.
Перед сменой ветки также удалите весь стенд.
