# Показ этапа 2: реплицированный список строк

Снимок `lab2` содержит выборы пяти узлов, строковый лог и встроенный UI этапа 2.
Рабочая разработка продолжается в `main`. Строки не исполняются как команды:
`SET x 42` — обычный текст; повторяющиеся и пустые строки допустимы.

## Автоматический прогон

Нужны Go версии из go.mod, Docker Compose и Python 3.9+.

```sh
go build ./...
go test ./...
go test -race ./...
go vet ./...
gofmt -l .
docker compose -p raftgo-scenarios -f scenarios/compose.yaml up -d --build
python3 scenarios/run.py all
```

В `lab2` команда `all` выполняет только task1–2. В полном `main` доступны
также следующие этапы; для приёмки этапа 2 запускайте `1` и `2` по очереди.
`PASS task1` и `PASS task2` означают, что проверены ответы HTTP, перевыборы,
отказ без большинства, догоняющая репликация и замена конфликтного хвоста.
В шаге 2.5 все follower приостановлены, а три из них отключены от сети до записи
(иначе TCP может доставить хвост из буферов после unpause). Поэтому хвост есть только
на старом лидере. Затем он приостанавливается, три реплики без хвоста подключаются обратно и выбирают
нового лидера, подтверждают запись нового term и заменяют хвост при возврате.
Старый запрос получает 409 либо 504; подтверждённый префикс сохраняется.
Runner снимает паузы через finally даже после ошибки и не повторяет запись.

## Ручной показ в браузере

1. Открыть `http://localhost:18001/`. Видны пять карточек, term, role,
   leader_id, текущие голоса, доступность и время опроса. Опросы неатомарны.
2. Выбрать follower, добавить `Привет 🌊`, ту же строку повторно, пустую строку
   и `<b>текст</b>`. Успех виден только после HTTP 201 с index/term.
   HTML отображается как текст. На каждой из пяти реплик строки совпадают;
   no-op, подтверждённые строки и неподтверждённый хвост различаются.
3. Через `docker compose -p raftgo-scenarios -f scenarios/compose.yaml pause nodeN`
   приостановить текущего лидера (подставить его ID), дождаться нового,
   добавить строку через доступный follower. Вернуть старого командой
   `unpause nodeN`: он становится follower и догоняет подтверждённый лог.
4. Приостановить один follower, добавить две строки, вернуть его и выбрать
   в UI: он догоняет список. Приостановленная реплика отмечена устаревшей.
5. Приостановить три follower, сразу отправить строку лидеру. Возможны 503
   или 504. Если запись принята до потери лидерства, виден неподтверждённый
   хвост; после 504 исход неизвестен. Автоповтора и ложного успеха нет.
   Снять паузы. Приостановка origin делает весь UI устаревшим.
6. Во время отдельного прогона `python3 scenarios/run.py 2` наблюдать шаг 2.5
   через `/status`/UI: хвост старого term заменяется подтверждённой записью
   нового term. Не управлять контейнерами вручную одновременно с runner.

`GET /status`, `/election`, `/log` — локальные наблюдения, а не безопасное
чтение общего состояния. Успех add означает commit и apply своей пары
index/term; не означает применение на всех follower к моменту ответа.

## Завершение

```sh
docker compose -p raftgo-scenarios -f scenarios/compose.yaml unpause
docker compose -p raftgo-scenarios -f scenarios/compose.yaml down
```

При переключении снимка сначала удалить весь свой стенд. Все состояния в RAM:
pause/unpause сохраняет term, голос и лог; stop/start отдельной ноды небезопасен.
Полный новый запуск создаёт новый пустой кластер.
