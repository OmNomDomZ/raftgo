## Что сохраняем

- В lab1 heartbeat уже выделен и не содержит репликацию будущего этапа.
  Сливать выборы и heartbeat в универсальный RPC-конвейер не предлагается:
  общая обвязка короткая, а смысл обработки ответов различается.
- Обработка higher term, dirty/sync, ошибки Storage, проверки RPC и таймеров
  поддерживают safety и тестируемость даже при Memory Storage. Удалять их
  ради размера кода нельзя. ReadIndex, no-op и index/term также сохраняются.
- KV Store — небольшой явный switch (62 строки весь файл lab3, 111 в lab4).
  Реестр обработчиков или отдельные классы команд здесь усложнят чтение.
- Go-клиент уже сводит операции к do. Его редиректы и ошибки отличаются от
  серверной пересылки, поэтому общий HTTP-framework не нужен.
- decodeKVBody намеренно проверяет точные поля и дубликаты; обычный decode
  имеет другой контракт. Объединение этих декодеров не является безопасным
  механическим рефакторингом.

## Выполнение и снимки

Все R1–R4 реализуются отдельно в main по прямому поручению пользователя.
Текущий autokanban допускает выполнение только S1–S4 с прежними суффиксами
(runner.py:select); новые R-ID им пока не запускаются. Расширение контроллера
не входит в этот анализ. Для начала: «Выполни R1».

Принятые lab1–lab4 не перемещаются. Эффект для них появится только после
отдельного явного поручения на пересдачу через DEMO: исходный SHA main,
подготовка кандидата в том же checkout, удаление будущих возможностей,
Go-набор, сценарии 1..N, ручной UI и проверка точного SHA. Уже существующие
snapshot/labN и принятые labN не перезаписывать в рамках R-карточек.
Сейчас не требуется ни новая DEMO-карточка, ни реализация рефакторинга.
