# API этапа 1

Swagger UI: `GET /swagger/`; OpenAPI: `GET /swagger/openapi.json`.
Swagger показывает только статус выборов и наблюдения пяти узлов.
Спецификация содержит только возможности этапа 1.
[Запуск и примеры](demo-launch.md).

`GET /status` и `GET /election` — alias с ответом 200, JSON `node`/`members`.

Пример начального ответа для узла с одним участником:

```json
{
  "node": {
    "id": "node1",
    "role": "Follower",
    "term": 0,
    "leader_id": "",
    "voted_for": "",
    "votes": 0,
    "quorum": 1,
    "running": false
  },
  "members": [
    {"id": "node1", "rpc_url": "http://node1:9000", "api_url": "http://node1:8000"}
  ]
}
```

Все поля `node` присутствуют даже при нулевых значениях; ID — строки,
term/счётчики — целые числа, running — boolean.

| Поле | Точная семантика |
| --- | --- |
| `id` | ID опрашиваемого узла |
| `role` | Последняя локальная роль: `Follower`, `Candidate`, `Leader` |
| `term` | Текущий локальный term |
| `leader_id` | Известный узлу лидер текущего term; `""` при неизвестном лидере или остановленном узле |
| `voted_for` | Кому этот узел отдал голос в текущем term; `""`, если не голосовал |
| `votes` | Число разных голосов, полученных текущим кандидатом, включая свой; в остальных ролях всегда 0 |
| `quorum` | Большинство фиксированного состава: floor(N/2) + 1, включая сам узел |
| `running` | Run уже запущен и его context ещё не завершён |

`members` — состав из конфигурации, включая сам узел, с полями `id`,
`rpc_url`, `api_url`; порядок соответствует конфигурации. Это не результат
проверки доступности. При создании API без состава (`nil`) возвращается `null`.

Статус снимается под mutex одного узла. Он может отставать и не доказывает
актуальное лидерство: несколько HTTP-опросов разных узлов не образуют атомарный
снимок кластера. Диагностика не выполняет кворумного барьера.
Наличие адреса в members или `running: true` не доказывает доступность узла
из браузера. При pause HTTP недоступен; последняя сохранённая карточка UI —
устаревшее наблюдение, а не новый статус.

`votes` не является историей или числом голосов избранного лидера. Повторный
ответ одного peer не увеличивает счётчик. Повторный RequestVote от кандидата,
за которого узел уже голосовал в этом term, получает тот же голос; другой
кандидат — отказ. При переходе кандидата в follower в том же term `voted_for`
сохраняется, а `votes` становится 0. Старший term сбрасывает `voted_for`;
heartbeat от лидера сам по себе не означает голос за него. При избрании
лидером `votes` также становится 0. Нельзя восстанавливать историю голосов
по `leader_id`. После завершения Run роль может остаться последней известной,
но `running: false` и `leader_id: ""`; это не действующий лидер.

Маршруты точные: `/status/` и `/election/child`, как и другие неизвестные
пути, возвращают 404. GET допускает query string; HEAD поддерживается HTTP
сервером с теми же заголовками и без тела. Другие методы на `/status` и
`/election` возвращают 405 с `Allow: GET, HEAD`.

## Экран выборов и агрегат

`GET /` отдаёт встроенный экран этапа 1, `/ui/election.css` и
`/ui/election.js` — его ресурсы. Нет CDN, dev-сервера и прямых межпортовых
запросов браузера. Неизвестные пути возвращают 404, изменяющие методы этих
маршрутов — 405; GET также поддерживает HEAD.

`GET /cluster/status` возвращает 200 даже при частичной недоступности:

```json
{"atomic":false,"members":[{"id":"node1","available":true,"observed_at":"2026-10-31T00:00:00Z","node":{"id":"node1","role":"Follower","term":1,"leader_id":"node2","voted_for":"node2","votes":0,"quorum":3,"running":true}},{"id":"node2","available":false,"error":"status unavailable"}]}
```

Массив содержит только фиксированный состав из конфигурации, в том же порядке.
Пример сокращён; на стенде пять участников. Опросы параллельны, общий дедлайн
600 мс с отменой по контексту запроса. Локальный участник читается напрямую,
остальные — через их настроенный `api_url/status`. Адреса должны быть доступны
**серверу**, а не только браузеру; для Docker используйте внутренние DNS-адреса
с API-портом контейнера. Redirect, proxy из окружения, адреса из query/ответов
соседей не используются; тело ответа ограничено 64 КиБ. Ошибочный JSON,
несовпадение ID, сетевой отказ и не-200 дают недоступного участника.

`observed_at` — время успешного локального наблюдения на сервере агрегатора,
не время выборов. HTTP-доступность не гарантирует доступности Raft RPC.
`atomic:false` означает независимые наблюдения; агрегат не доказывает кворум.
Ответ не кэшируется. В нём только поля выборов.

UI обновляется через секунду после ответа (без перекрытия опросов), запрос
браузера ограничен двумя секундами. Последние успешные данные сохраняются
только в открытой вкладке; при ошибке участника сразу помечаются устаревшими,
при отсутствии свежего ответа — через 3 секунды. Если недоступен сам origin,
возраст продолжает расти. До первого успеха значения неизвестны. Строки
показываются через `textContent`, голоса предыдущих term не реконструируются.
