# Диагностика узла и строковый лог

`GET /status` и `GET /election` — точные alias: возвращают 200,
`Content-Type: application/json` и объект с `node`, `members`, `consistency: "local"` и `entries`.
В main оба маршрута сохраняют полный статус, включая поля лога.
`GET /log`, `POST /entries` и все маршруты CRUD/CAS/lock также сохранены.
Контракты остальных операций описаны в [README](../README.md) и
[контракте этапов](stages.md).

Пример начального ответа main для узла с одним участником:

```json
{
  "node": {
    "id": "node1",
    "role": "Follower",
    "term": 0,
    "leader_id": "",
    "voted_for": "",
    "votes": 0,
    "quorum": 1,
    "commit_index": 0,
    "last_log_index": 0,
    "running": false
  },
  "consistency": "local",
  "entries": [],
  "members": [
    {"id": "node1", "rpc_url": "http://node1:9000", "api_url": "http://node1:8000"}
  ]
}
```

Все поля `node` присутствуют даже при нулевых значениях; ID — строки,
term/индексы/счётчики — целые числа, running — boolean.

| Поле | Точная семантика |
| --- | --- |
| `id` | ID опрашиваемого узла |
| `role` | Последняя локальная роль: `Follower`, `Candidate`, `Leader` |
| `term` | Текущий локальный term |
| `leader_id` | Известный узлу лидер текущего term; `""` при неизвестном лидере или остановленном узле |
| `voted_for` | Кому этот узел отдал голос в текущем term; `""`, если не голосовал |
| `votes` | Число разных голосов, полученных текущим кандидатом, включая свой; в остальных ролях всегда 0 |
| `quorum` | Большинство фиксированного состава: floor(N/2) + 1, включая сам узел |
| `running` | Run уже запущен и его context ещё не завершён |
| `commit_index` | Локально известная граница подтверждённого префикса (main, этапы 2–4) |
| `last_log_index` | Конец локального лога, включая неподтверждённый хвост (main, этапы 2–4) |

`members` — состав из конфигурации, включая сам узел, с полями `id`,
`rpc_url`, `api_url`; порядок соответствует конфигурации. Это не результат
проверки доступности. При создании API без состава (`nil`) возвращается `null`.

`node` и `entries` получены одним вызовом `InspectLog` под mutex одного узла.
Снимок может отставать и не доказывает
актуальное лидерство: несколько HTTP-опросов разных узлов не образуют атомарный
снимок кластера. Для диагностики нет ReadIndex/кворумного барьера.
Наличие адреса в members или `running: true` не доказывает доступность узла
из браузера. При pause HTTP недоступен; последняя сохранённая карточка UI —
устаревшее наблюдение, а не новый статус.

`votes` не является историей или числом голосов избранного лидера. Повторный
ответ одного peer не увеличивает счётчик. Повторный RequestVote от кандидата,
за которого узел уже голосовал в этом term, получает тот же голос; другой
кандидат — отказ. При переходе кандидата в follower в том же term `voted_for`
сохраняется, а `votes` становится 0. Старший term сбрасывает `voted_for`;
heartbeat от лидера сам по себе не означает голос за него. При избрании
лидером `votes` также становится 0. Нельзя восстанавливать историю голосов
по `leader_id`. После завершения Run роль может остаться последней известной,
но `running: false` и `leader_id: ""`; это не действующий лидер.

Маршруты точные: `/status/` и `/election/child`, как и другие неизвестные
пути, возвращают 404. GET допускает query string; HEAD поддерживается HTTP
сервером с теми же заголовками и без тела. Другие методы на `/status` и
`/election` возвращают 405 с `Allow: GET, HEAD`.

## Строковый лог и add (main, этап 2 и выше)

`entries` всегда массив (пустой лог — `[]`). Запись содержит `index`, `term`,
`kind` (`command` или `noop`), `command` (строка, в том числе пустая) и
`committed` (`index <= node.commit_index`). `node.last_log_index` равен длине
массива. No-op виден отдельно от пустой пользовательской строки. Хвост с
`committed: false` может быть заменён. `/log` сохраняет тот же локальный
снимок без members. Ни один из этих маршрутов не требует лидера или кворума.

`POST /entries` принимает ровно один JSON-объект `{"command":"строка"}`,
без неизвестных полей. Пустая строка допустима; одинаковые строки получают
разные индексы. Лимит — 65536 байт декодированной UTF-8 строки включительно,
а не число символов или размер JSON с escape-последовательностями.
Неверный UTF-8, JSON, тип, отсутствие/null command, превышение лимита и
внутренний префикс `raftgo:kv:v1:` дают 400 до предложения записи.
Защита KV сохраняется в main; при выделении lab2 KV-декодер удаляется.

201 с `index`, `term`, `committed: true` означает, что apply consumer обработал
именно эту пару index/term. Commit без apply недостаточен. Применение другой
записи на этом индексе даёт 409. Follower возвращает 307 с Location известного
лидера (сам запрос не пересылает), неизвестный лидер — 503 с Retry-After: 1.
Через 5 секунд ожидания или при отмене запроса — 504 с index/term и неизвестным
исходом. Это не откат: запись может примениться позже. Сервер не повторяет
предложение, клиент не должен автоматически повторять запись после 504 или
потери ответа; дедупликации нет. Следование 307 сохраняет метод и тело.

## Выделение lab1 в S1-DEMO

В [raft/inspect.go](../raft/inspect.go) выделены `ElectionStatus` и
`Status.Election()`: представление только восьми полей выборов (`id`, `role`,
`term`, `leader_id`, `voted_for`, `votes`, `quorum`, `running`), без полей лога.
В main это вспомогательный контракт для переноса, оба HTTP alias продолжают
возвращать полный `Status`. Это не переключатель режима приложения.

При подготовке снимка по [delivery.md](delivery.md) перенести ядро S1-CORE
из исторической `stage/1-election`, согласовать его Status с ElectionStatus
и перенести тесты семантики выборов/маршрутов. В снимке оба alias должны
возвращать только эти восемь полей в node и members в envelope. Удалить
полный Status/InspectLog, реализацию лога и будущих операций вместе с их
маршрутами и тестами. Проверить точный JSON и 404 для `/entries`, `/log`,
CRUD/CAS/lock на кандидате lab1. Проверка отсутствия этих функций и приёмка
снимка выполняются только в S1-DEMO; полный main сохраняется.

## Экран выборов и агрегат

`GET /` отдаёт встроенный экран этапа 1, `/ui/election.css` и
`/ui/election.js` — его ресурсы. Нет CDN, dev-сервера и прямых межпортовых
запросов браузера. Неизвестные пути возвращают 404, изменяющие методы этих
маршрутов — 405; GET также поддерживает HEAD.

`GET /cluster/status` возвращает 200 даже при частичной недоступности:

```json
{"atomic":false,"members":[{"id":"node1","available":true,"observed_at":"2026-10-31T00:00:00Z","node":{"id":"node1","role":"Follower","term":1,"leader_id":"node2","voted_for":"node2","votes":0,"quorum":3,"running":true}},{"id":"node2","available":false,"error":"status unavailable"}]}
```

Массив содержит только фиксированный состав из конфигурации, в том же порядке.
Пример сокращён; на стенде пять участников. Опросы параллельны, общий дедлайн
600 мс с отменой по контексту запроса. Локальный участник читается напрямую,
остальные — через их настроенный `api_url/status`. Адреса должны быть доступны
**серверу**, а не только браузеру; для Docker используйте внутренние DNS-адреса
с API-портом контейнера. Redirect, proxy из окружения, адреса из query/ответов
соседей не используются. `/status` сериализует `node` перед логом; агрегат
читает только JSON-префикс до конца `node` (максимум 64 КиБ), затем закрывает
ответ. Растущий лог не загружается и не делает живой узел недоступным.
Неверный JSON в прочитанном префиксе, отсутствие node, несовпадение ID,
сетевой отказ и не-200 дают недоступного участника. Неиспользованный остаток
ответа агрегат не валидирует.

`observed_at` — время успешного локального наблюдения на сервере агрегатора,
не время выборов. HTTP-доступность не гарантирует доступности Raft RPC.
`atomic:false` означает независимые наблюдения; агрегат не доказывает кворум.
Ответ не кэшируется. В нём только поля выборов, полный `/status` main сохранён.

UI обновляется через секунду после ответа (без перекрытия опросов), запрос
браузера ограничен двумя секундами. Последние успешные данные сохраняются
только в открытой вкладке; при ошибке участника сразу помечаются устаревшими,
при отсутствии свежего ответа — через 3 секунды. Если недоступен сам origin,
возраст продолжает расти. До первого успеха значения неизвестны. Строки
показываются через `textContent`, голоса предыдущих term не реконструируются.

Для выделения lab1 использовать election-only экран принятого lab1 либо удалить
форму/лог/JS этапа 2 и подключение `logUI` из кандидата. Агрегатор `electionUI`
использует `Status().Election()`; в выделенном ядре заменить на `Status()`.
Само удаление будущего core/API и проверка снимка выполняются только в DEMO.

## Same-origin форма строкового лога (этап 2)

`GET /cluster/log/{id}` возвращает локальный `/status` выбранного участника
(для своего ID — напрямую), включая consistency=local, node и entries из
одного InspectLog. Только ID из фиксированной конфигурации Handler;
неизвестный ID — 404, недоступный peer или redirect — 503. Удалённый опрос
ограничен 600 мс, лог передаётся потоком без ограничения количества записей;
обрыв/таймаут и неполный JSON не считаются успешным снимком.

`POST /cluster/entries/{id}` принимает то же JSON-тело, что `/entries`.
Отправляет его только на настроенный api_url участника, затем следует явным
307 исключительно на точный api_url/entries другого фиксированного участника.
Посещённый адрес не повторяется; цикл или посторонний Location дают 503.
Обычный `POST /entries` сохраняет 307 для curl/Go-клиента.
У формы нет произвольных URL/путей, forwarding cookies/токенов, proxy окружения
и обращений браузера к другим origin. Query и состав из ответов игнорируются.
Методы других видов — 405, диагностические ответы — no-store.

Общий дедлайн пересылки записи — 8 секунд, ожидание commit/apply на лидере —
5 секунд. Ответ API, включая 201/400/409/503/504 и index/term, передаётся форме.
Сетевая ошибка или потеря ответа после отправки превращается в 504 с неизвестным
исходом. Ни после неё, ни после 503/504 повторной отправки нет. Только явный
307 означает, что follower отклонил запись и разрешает пересылку к лидеру.
Без подтверждения нельзя обещать отсутствие записи или безопасный повтор.

В UI выберите участника для просмотра и отправки. Два независимых цикла опроса
(выборы и выбранный лог) запускаются через секунду после ответа, запросы GET
браузера ограничены 2 секундами. Последний успешный лог сохраняется во вкладке
с отметкой устаревания после ошибки или 3 секунд без успеха. Это локальное
наблюдение, не линейризуемое чтение и не атомарный снимок нескольких реплик.
Строки показаны как JSON-строки через textContent: пустая строка — `""`,
служебный no-op — отдельный вид. Committed и неподтверждённый хвост подписаны
и различаются цветом. Форма принимает до 65536 байт UTF-8 (проверяется также
сервером), сохраняет текст, блокирует отправку на время ожидания и не повторяет
POST автоматически. Браузерный дедлайн записи — 9 секунд; потеря ответа также
показывает неизвестный исход и риск дубликата при повторном нажатии.

Docker-конфиги задают `internal_api_url` (например `http://node1:8080`) для
серверных опросов и пересылки UI; публичный `api_url` остаётся адресом хоста
для 307. Без внутреннего адреса используется `api_url`. Оба адреса фиксированы
конфигурацией, валидируются и не берутся из браузерного запроса или ответа
диагностики. Сервер сопоставляет точный публичный Location известного участника
с его внутренним адресом; произвольный редирект не разрешён.
