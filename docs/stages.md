# Контракт этапа 2

Пять узлов фиксированного состава выбирают лидера и реплицируют упорядоченный
список UTF-8 строк. Строки не интерпретируются; дубликаты и пустая строка допустимы.

POST /entries принимает {"command":"строка"}, максимум 65536 байт после JSON
декодирования. HTTP 201 возвращает index, term и committed=true только после
commit и apply своей пары index/term. Follower отвечает 307 на известного лидера,
без лидера — 503. 409 означает замену записи до commit; 504 — неизвестный исход,
а не откат. Автоматических повторов нет. Выборы добавляют служебный no-op.

GET /status и /election содержат node, members, consistency="local", entries.
GET /log содержит тот же локальный снимок node и entries. В записи index, term,
kind (command/noop), command, committed. node и entries сняты одним InspectLog.
Хвост может быть неподтверждённым. Диагностика не предоставляет общего
атомарного снимка кластера. Голос voted_for — текущего term, votes — текущей
кандидатуры; история голосов не восстанавливается из текущего статуса.

GET / — встроенный UI этапа 2. Карточки пяти узлов, времена опроса и устаревание,
форма строки, выбор реплики, текстовый вывод лога. Служебные записи и хвост
различимы. Успех только после 201. Browser использует тот же origin;
серверные маршруты ограничены фиксированным составом участников.

Memory Storage синхронно и атомарно сохраняет term, голос и лог, возвращает
глубокие копии. Это допущение безопасной памяти в модели: pause/unpause и
изоляция сохраняют RAM. Завершение процесса уничтожает память. Полный новый
запуск всех процессов — новый пустой кластер. Stop/start одной ноды под прежним
ID в работающем кластере небезопасен. Файлов состояния и data volumes нет.

Ядро Raft зависит от интерфейсов Storage, Transport, Clock, не от HTTP.
Core-тесты используют fake-транспорт и виртуальное время. Сохраняются Election
Safety, Log Matching, Leader Completeness и State Machine Safety; commit
продвигается по кворуму только через запись текущего term.
