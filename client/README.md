# Go-клиент KV

Пакет `raftgo/client` обращается только к HTTP API, без CLI и внешних
зависимостей. `New("http://localhost:8001", nil)` разрешает до пяти переходов
307. Через `Options` задаются `HTTPClient` и `MaxRedirects`; ноль запрещает
переходы. Переданный http.Client копируется, его CheckRedirect заменяется,
Transport/Jar используются совместно. Transport не должен самостоятельно
повторять записи. Timeout охватывает всю цепочку переходов и чтение ответа;
по умолчанию используйте context с дедлайном или настройте HTTPClient.Timeout.

Все методы возвращают `(Result, error)` и принимают context:

```go
Create(ctx, key, value, token)
Get(ctx, key, token)
Put(ctx, key, value, token)
Delete(ctx, key, token)
CAS(ctx, key, expected, value, token)
Lock(ctx, key)
Unlock(ctx, key, token)
```

Пустой token означает отсутствие заголовка. Владельцу нужно явно передавать
`Lock(...).Token`; клиент не хранит и не распространяет токены автоматически.
`Result` содержит Value, Token и Index/Term применённой записи. Ошибки сервера
возвращают тот же Result и `*HTTPError` (StatusCode, Result).
Для 404/409/423/503 используйте `errors.Is` с ErrNotFound/ErrConflict/ErrLocked/
ErrUnavailable; подробности доступны через `errors.As` в `*HTTPError`.

Только 307 переносит запрос с тем же методом, телом и токеном; циклы и превышение
лимита дают ErrRedirect. Другие 3xx возвращаются как HTTPError. Принимаются
HTTP(S) адреса без credentials; URL лидера должен относиться к доверенному
кластеру. Клиент не запоминает лидера между операциями.

504 для записи, сетевая ошибка, отмена/timeout во время запроса или повреждённый
успешный ответ дают `*UnknownOutcomeError` и `errors.Is(err, ErrUnknownOutcome)`.
Исходная ошибка доступна через Unwrap, в том числе context.Canceled,
context.DeadlineExceeded и HTTPError 504 с Index/Term. GET не помечается как
неизвестная запись. Отмена до отправки возвращает обычную ошибку context.

Ни один изменяющий запрос не повторяется автоматически после ошибки. 307 —
перенаправление отклонённого follower запроса, а не повтор уже принятой команды.
Exactly-once не гарантируется: дедупликации нет, потерянный ответ не отменяет
commit, а ручной повтор может исполниться ещё раз. Даже повторный PUT или CAS
может затереть промежуточное изменение другого клиента. После неизвестного
исхода приложение должно отдельно установить состояние, учитывая конкуренцию;
успешный GET сам по себе не доказывает судьбу первоначальной команды.

CAS сравнивает строку, ABA не обнаруживает. Lock без TTL, не реентерабелен,
остаётся после удаления значения. Потеря токена может оставить ключ занятым.
Токен не аутентификация; fencing действует только в одной жизни кластера,
после полного сброса памяти старые токены использовать нельзя.

[Компилируемый пример двух клиентов](example_test.go) показывает владельца и
конкурента, CAS и явный Unlock. Он требует работающий кластер на портах 8001/8002;
`go test` компилирует пример без обращения к внешнему кластеру. Интеграционный
тест запускает настоящий Raft/API в httptest и проверяет гонки двух клиентов,
токены и потерю ответа после apply без повторной команды.
