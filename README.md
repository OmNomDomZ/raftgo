# raftgo — лабораторная 1

Пять узлов Raft: выборы лидера, heartbeat, term и голоса, Memory Storage,
HTTP-диагностика и Swagger. Кворум фиксирован: три из пяти.
Пользовательского лога и операций следующих лабораторных в lab1 нет.

## Запуск

На macOS запустите Docker Desktop, затем из корня проекта:

```sh
python3 scripts/demo.py
```

Откроются пять окон Terminal с логами node1–node5.

- Swagger: http://localhost:18001/swagger/
- Swagger остальных узлов: порты 18002–18005, путь `/swagger/`.
- В Swagger доступен только `GET /status` открытого узла.
- `/`, `/ui/...`, `/election` и `/cluster/status` удалены и возвращают 404.

Один стенд описан в корневом `compose.yaml`, состав узлов — в
`config/cluster.json`. Имя проекта `raftgo-scenarios` задано в Compose,
поэтому обычные команды из корня управляют тем же стендом.
При существующих контейнерах demo.py только открывает логи, без пересборки
и перезапуска. Закрытие окна прекращает просмотр логов, а не работу узла.

## Показ отказа и остановка

Подставьте ID фактического лидера, например node3:

```sh
docker compose pause node3
docker compose unpause node3
```

Pause/unpause сохраняют RAM. Отдельный stop/start не используйте для возврата
узла в продолжающийся кластер: его term и голос будут потеряны.
Для завершения показа или полной пересборки:

```sh
docker compose unpause
docker compose down
```

Down удаляет весь стенд и его состояние в RAM. Следующий запуск создаёт новый
пустой кластер. Перед сменой ветки также удаляйте весь текущий стенд.
Инструкции других веток могут использовать прежний сценарный Compose.

## Код и материалы

- `cmd/raftgo/` — создание зависимостей и запуск узла.
- `raft/` — ядро выборов и heartbeat.
- `server/` — входящие HTTP/RPC, локальный статус и Swagger.
- `transport/` — исходящие RPC по HTTP.
- `storage/` — состояние в памяти процесса.
- `scripts/demo.py` — запуск и пять окон с логами.
- `tests/scenarios.py` — автоматическая проверка работающего кластера.

[Краткая инструкция показа](docs/demo-launch.md), [API](docs/api.md),
[контракт этапов](docs/stages.md), [автоматическая проверка](tests/README.md).

## Проверки

```sh
go build ./...
go test ./...
go test -race ./...
go vet ./...
python3 tests/scenarios.py 1
```

Для последней команды нужен запущенный стенд. При этой доработке по поручению
пользователя приложение, Docker и тесты не запускались.
