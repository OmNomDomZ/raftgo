# raftgo — лабораторная 2

Пять узлов Raft: выборы, heartbeat и реплицированный список UTF-8 строк.
Данные хранятся в RAM. Запись подтверждается после commit и apply; кворум —
три из пяти. KV, CAS и блокировок в этом этапе нет.

## Запуск

На macOS запустите Docker Desktop, затем из корня:

```sh
python3 scripts/demo.py
```

Откроются пять окон Terminal с логами node1–node5.
Swagger: http://localhost:18001/swagger/; другие узлы — порты 18002–18005.
Встроенный UI, `/election`, `/cluster/status` и `/cluster/log/{id}` удалены.

Один стенд описан в корневом `compose.yaml`, состав — в `config/cluster.json`.
Имя проекта — `raftgo-scenarios`. Обычные команды `docker compose` из корня
управляют теми же узлами. При существующих контейнерах demo.py только открывает
логи, без пересборки и перезапуска. Закрытие окна не останавливает контейнер.

## Добавление строки

В Swagger выполните `POST /cluster/entries/{id}`, например с id=node1:

```json
{"command":"Привет, Raft!"}
```

Выбранный узел передаст запрос лидеру. Успех — HTTP 201 с index, term и
committed=true. Пустые и повторяющиеся строки допустимы; лимит — 64 КиБ UTF-8.
`GET /status` и `GET /log` показывают локальное состояние открытого узла.
Для сравнения реплик откройте Swagger на их портах. No-op — служебная запись,
а неподтверждённый хвост ещё может измениться. После 504 или потери ответа
исход неизвестен: повторное Execute может добавить дубликат.

## Отказы и остановка

Подставьте нужный ID, например node3:

```sh
docker compose pause node3
docker compose unpause node3
```

Pause/unpause сохраняют RAM. Stop/start отдельного узла с пустой памятью
под прежним ID в продолжающемся кластере небезопасен.
Полный сброс перед сменой ветки или пересборкой:

```sh
docker compose unpause
docker compose down
```

Следующий запуск создаст новый пустой кластер.
