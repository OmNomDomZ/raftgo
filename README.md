# raftgo · lab3

Снимок этапа 3: выборы пяти узлов, реплицированный список строк и KV CRUD.
Разработка продолжается в main. [Показ и проверки](docs/demo3.md),
[API](docs/api.md), [устройство](docs/onboarding.md).

```sh
docker compose up -d --build
```

Откройте http://localhost:8001/ (также 8002–8005): встроенный UI этапа 3
показывает роли, term, текущие голоса, независимые локальные статусы и лог.
Форма add сохраняет пустые и повторяющиеся строки; no-op обозначены отдельно.
CRUD имеет независимый выбор участника и отдельный результат GET.
Все ресурсы встроены в Go-бинарник, без CDN и отдельного frontend-сервера.

| Запрос | Результат |
| --- | --- |
| GET /status, /election | node, members, entries, consistency=local |
| GET /log | Локальный лог с committed и неподтверждённым хвостом |
| POST /entries | `{"command":"строка"}`, 201 после commit/apply |
| POST /kv/{key} | `{"value":"строка"}`, создание 201, повтор 409 |
| PUT /kv/{key} | Upsert 200 |
| GET /kv/{key} | ReadIndex + apply, 200 или 404 |
| DELETE /kv/{key} | Удаление 200, отсутствующий 404 |

Ключ — один URL-экранированный сегмент, 1..1024 байта UTF-8. Пустые строки,
Unicode и JSON-подобные значения допустимы. Внутренняя KV-команда ограничена
65536 байтами вместе с JSON и префиксом. /entries не исполняет строки как KV,
зарезервированный внутренний префикс отклоняется.

Follower отвечает 307 (curl -L сохраняет метод/тело); неизвестный лидер — 503.
UI обращается same-origin к фиксированным участникам и следует только 307
того же ключа. 504 записи означает неизвестный исход; автоматических повторов
нет. GET не использует диагностические снимки вместо кворумного барьера.

Конфиг config/cluster.json: listen, rpc_listen, фиксированные members с id,
rpc_url, публичным api_url и internal_api_url для серверного опроса/UI.
Вся память процесса сохраняется при docker compose pause/unpause.
Stop/start отдельного узла с пустой памятью небезопасен; down/up всего стенда
создаёт новый пустой кластер. Нет файлов состояния или data volumes.

```sh
go build ./...
go test -count=1 ./...
go test -race -count=1 ./...
go vet ./...
gofmt -l .
docker compose -p raftgo-scenarios -f scenarios/compose.yaml up -d --build
python3 scenarios/run.py all
```

Сценарный стенд использует отдельные порты 18001–18005. all запускает task1–3.
После проверки выполните unpause и down для своего стенда (см. docs/demo3.md).
Не управляйте нодами вручную одновременно с runner.
